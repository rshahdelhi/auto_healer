AH Auto Healer Resilience Operations

API Documentation

HTTP endpoints for ingesting monitoring events and presenting stored incident data.

Dashboard Console Swagger OpenAPI JSON

Run the service

uv run auto-healer --host 127.0.0.1 --port 8080 --db auto_healer.sqlite3

Endpoints

GET /health

Returns service health.

POST /events

Accepts a monitoring event from Dynatrace, Splunk, Phoenix, or another JSON producer.

POST /splunk/alerts

Accepts Splunk alert payloads for system and application errors.

GET /events

Lists stored events. Supports project_id, project_name, component, and limit query parameters.

POST /policies

Saves scale limits and holiday/off-hours stop settings for a project component.

GET /policies

Lists saved application policies for the presentation layer.

POST /endpoint-config

Saves the Auto Healer endpoint URL and ADFS authentication settings.

GET /endpoint-config

Returns the current endpoint configuration without returning the saved password.

GET /audit-log

Lists audit trail entries for policy/rule and endpoint configuration changes.

POST /postmortems

Creates or updates blameless postmortem and RCA records for SRE reviews.

GET /postmortems

Lists saved postmortems by incident, project, component, or status.

Event payload

Each event requires component and at least one project identifier.

Project fields

  • project_id, projectId, or pid
  • project_name, projectName, or project

Optional aliases

  • source or monitoring_system
  • severity or level
  • title or event_name
  • message or description

Example request

curl -X POST http://127.0.0.1:8080/events \
  -H 'Content-Type: application/json' \
  -d '{
    "project_id": "checkout",
    "project_name": "Checkout",
    "component": "payments-api",
    "source": "dynatrace",
    "severity": "critical",
    "message": "p95 latency crossed threshold"
  }'
